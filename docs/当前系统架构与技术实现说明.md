# 当前系统架构与技术实现说明

## 1. 文档范围

这份文档描述的是当前仓库真实实现，不是历史规划稿，也不是理想架构图。

VigilAI 现在已经不是单一“机会列表系统”，而是三个并行表面：

- `/` 系统首页
- `/opportunity/*` 结构化机会工作台
- `/agent` 共享 Agent 工作台
- `/selection/*` 结构化选品工作台

旧的平铺路由如 `/workspace`、`/activities` 仍然保留，但只是兼容跳转，不再是主路径。

## 2. 体验层

### 2.1 机会工作台

正式路径：

- `/opportunity/workspace`
- `/opportunity/dashboard`
- `/opportunity/activities`

- `/opportunity/analysis/results`
- `/opportunity/analysis/templates`

- `/opportunity/digests`
- `/opportunity/sources`

### 2.2 共享 Agent 工作台

- `/agent`

这是会话优先的界面，背后由共享 Agent 平台支撑。

### 2.3 选品工作台

- `/selection/workspace`
- `/selection/opportunities`
- `/selection/opportunities/:id`
- `/selection/compare`
- `/selection/tracking`

## 3. 前端结构

### 3.1 顶层路由

前端路由拆分定义在：

- `app/frontend/src/App.tsx`

当前结构是：

- `SystemHomePage` 负责 `/`
- `DomainShellLayout` 负责各域外壳
- `WorkspacePage` 负责机会工作台主页
- `AgentWorkspacePage` 负责共享 Agent 页
- `SelectionWorkspacePage` 负责选品主页

共享路径常量定义在：

- `app/frontend/src/routes/domainPaths.ts`

### 3.2 机会域页面组成

机会域仍然是典型的 page-oriented 结构，不是 session-oriented 结构。

主要页面链路：

- `WorkspacePage`
- `ActivitiesPage`
- `ActivityDetailPage`
- `TrackingPage`
- `DigestsPage`
- `SourcesPage`
- `AnalysisResultsPage`
- `AnalysisTemplatesPage`

主要前端 Hook：

- `useWorkspace`
- `useActivities`
- `useTracking`
- `useDigests`
- `useSources`
- `useAnalysisTemplates`
- `useAgentAnalysisJobs`

前端 API 访问仍集中在：

- `app/frontend/src/services/api.ts`

## 4. 后端结构

### 4.1 共享平台层

共享 Agent 平台代码位于：

- `app/backend/agent_platform/`

职责包括：

- session 持久化
- turn 持久化
- artifact 持久化
- tool routing
- conversation reply 组装

关键模块：

- `repository.py`
- `artifact_service.py`
- `conversation_engine.py`
- `tool_router.py`

### 4.2 机会域

机会域仍然主要由 legacy SQLite + `DataManager` 驱动。

关键代码：

- `app/backend/data_manager.py`
- `app/backend/data_manager_components/activity.py`
- `app/backend/data_manager_components/analysis.py`
- `app/backend/data_manager_components/workspace.py`
- `app/backend/opportunity_domain/`

需要明确的一点：

当前结构化机会工作台并没有彻底拆成独立 service layer，它仍然围绕 `DataManager` 这个大门面运转。

### 4.3 选品域

选品域代码位于：

- `app/backend/product_selection/`

它比机会域更明确地按 repository / service / adapter 分层：

- `repository.py`
- `service.py`
- `adapters/*`

## 7. 启动与运行时说明

- 后端启动时会初始化 `DataManager`、`TaskScheduler`、`ToolRouter`、`ConversationEngine`、`ArtifactService`
- `app/backend/main.py` 里调度器启动和自动初始刷新当前都被关闭了
- 机会域结构化页面仍然依赖 `DataManagerWorkspaceMixin` 里的同步聚合逻辑

## 8. 当前实现取舍

1. 路由边界已经比以前清楚，但机会工作台底层仍然保留明显的 legacy 形态  
2. `DataManager` 仍然过宽，混合了承载：
   - 列表
   - 打分
   - 详情组装
   - 跟进
   - 日报
   - 工作台聚合  
3. 多个机会域 API 仍然存在 `fetchall()` 后再 Python 过滤的模式，当前规模还可接受，大规模数据下不理想  
4. 共享 Agent 平台是 additive 的，并没有取代结构化机会工作台
